# C4 · 3D-лобби Clickable

Неоновая карусель игровых автоматов: единая точка входа во все конференционные демо. Автомат открывает свою игру с пролётом камеры в экран. Лобби и все игры собираются в один статический сайт, который работает на Vercel и офлайн с ноутбука.

Дизайн: `docs/superpowers/specs/2026-10-30-c4-lobby-design.md`. План: `docs/superpowers/plans/2026-10-30-c4-lobby.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | лобби в режиме разработки; игры берутся из последней `build:games`, плюс тестовая игра-заглушка `TEST GAME` |
| `npm run build:games` | собирает игры из `games.config.json` в `.games-build/<id>/` и пишет `manifest.json` (`--strict` — код 1, если какая-то игра не собралась) |
| `npm run record:previews` | записывает видеопревью собранных игр в `public/previews/` (нужен GPU; повторять после обновления игр) |
| `npm run build` | собирает лобби в `dist/` и копирует туда собранные игры (`dist/games/<id>/`) |
| `npm run build:all` | всё вместе: игры, лобби, проверка сайта |
| `npm run check:games` | открывает собранный сайт в headless Chrome и ищет 404 и запросы за пределы папки игры |
| `npm run serve` | раздаёт `dist/` на `http://localhost:4173` |
| `npm test` | юнит-тесты (Vitest) |
| `npm run e2e` | браузерные тесты (Playwright) |

## Как добавить игру

Одна строка в `games.config.json`:

```json
{ "id": "mines-crystal", "title": "CRYSTAL MINES", "subtitle": "Open crystals, dodge the bombs", "source": "../mines-crystal" }
```

- `id` — путь на сайте: `/games/<id>/`.
- `source` — папка игры относительно `demos/lobi-3d/` (по умолчанию `../<id>`). Когда игры переедут внутрь лобби, достаточно поменять это поле.
- Необязательные поля: `ownExit` (у игры есть своя кнопка выхода в embed-режиме), `revealDelayMs`, `idleReturnSec`, `preview`, `poster`.

Пока игра не собрана или сборка упала, её автомат показывает COMING SOON. Если игр меньше шести, свободные места занимают автоматы COMING SOON с логотипом.

## Контракт для игр

Полностью в разделе 13 спеки. Коротко:

1. Игра работает из подпапки `/games/<id>/`: пути к ассетам только относительные или через `import.meta.env.BASE_URL`.
2. Собирается командой `vite build` (лобби подставляет `--base` и `--outDir` само, конфиг игры не трогает).
3. `?embed=1` — без собственного экрана загрузки.
4. Выход: `window.parent.postMessage({ type: 'clickable:exit' }, '*')`.
5. Рекомендуется: `clickable:ready`, когда сцена готова; слушать `clickable:visible` и `clickable:mute`.

Если игра чего-то из этого не умеет, у лобби есть запасной путь: само определяет готовность по canvas, Esc и угловая кнопка `← LOBBY` выводят в лобби.

## Видеопревью

`npm run record:previews` открывает каждую собранную игру в Chrome на GPU, нажимает пробел каждые 3,5 с и пишет 15-секундный ролик 640×360 и постер. Лобби подхватывает их из `public/previews/index.json` при старте. Видео играет только на активном автомате, остальные показывают постер. Ролики не коммитятся (их нужно перезаписывать при каждом обновлении игр). Если превью нет, на экране неоновая заставка с названием.

## На стенде (офлайн)

```bash
npm run build:games
npm run record:previews
npm run build:all
npm run serve
# Chrome в режиме киоска: Esc не выбрасывает из полноэкранного режима
chrome --kiosk http://localhost:4173
```

## Деплой на Vercel

Только после подтверждения заказчика:

```bash
npm run build:all
npx vercel deploy dist --prod
```

`dist/vercel.json` (из `public/`) задаёт долгий кеш для хешированных ассетов.

## Клавиши

| Клавиша | Действие |
|---|---|
| ← / → или A / D | повернуть карусель |
| Enter / пробел | открыть игру |
| Esc | выйти из игры |
| 1–9 | сразу открыть N-ю игру (ведущий) |
| M | звук вкл/выкл |
| F | счётчик FPS |
| T | attract-режим вкл/выкл |

Параметры URL для ведущего и тестов: `?fps=1`, `?idle=<сек>` (возврат из игры по простою), `?attractIdle=<сек>`, `?tg=<query>` (параметры тестовой игры в dev).
