# C4 · 3D-лобби Clickable

Неоновая карусель игровых автоматов: единая точка входа во все конференционные демо. Автомат открывает свою игру с пролётом камеры в экран. Лобби и все игры собираются в один статический сайт, который работает на Vercel и офлайн с ноутбука.

Дизайн: `docs/superpowers/specs/2026-10-30-c4-lobby-design.md`. План: `docs/superpowers/plans/2026-10-30-c4-lobby.md`.

## Команды

| Команда | Что делает |
|---|---|
| `npm run dev` | лобби в режиме разработки; игры берутся из последней `build:games`, плюс тестовая игра-заглушка `TEST GAME` |
| `npm run build:games` | собирает игры из `games.config.json` в `.games-build/<id>/` и пишет `manifest.json` (`--strict` — код 1, если какая-то игра не собралась) |
| `npm run record:previews` | записывает видеопревью собранных игр в `public/previews/` (нужен GPU; повторять после обновления игр) |
| `npm run build` | собирает лобби в `dist/` и копирует туда собранные игры (`dist/games/<id>/`) |
| `npm run build:all` | всё вместе: игры, лобби, проверка сайта |
| `npm run check:games` | открывает собранный сайт в headless Chrome и ищет 404 и запросы за пределы папки игры |
| `npm run serve` | раздаёт `dist/` на `http://localhost:4173` |
| `npm test` | юнит-тесты (Vitest) |
| `npm run e2e` | браузерные тесты (Playwright) |

## Как добавить игру

Одна строка в `games.config.json`:

```json
{ "id": "mines-crystal", "title": "CRYSTAL MINES", "subtitle": "Open crystals, dodge the bombs", "source": "../mines-crystal" }
```

- `id` — путь на сайте: `/games/<id>/`.
- `source` — папка игры относительно `demos/lobi-3d/` (по умолчанию `../<id>`). Когда игры переедут внутрь лобби, достаточно поменять это поле.
- Необязательные поля: `waitForReady: true` (игра надёжно шлёт `clickable:ready`, показывать только по нему, а не по появлению canvas), `revealDelayMs` (задержка показа после сигнала готовности), `sendVisible: false` (не отправлять `clickable:visible` игре, которая по нему сама уходит со стартового экрана), `idleReturnSec`, `preview`, `poster`.

Пока игра не собрана или сборка упала, её автомат показывает COMING SOON. Если игр меньше шести, свободные места занимают автоматы COMING SOON с логотипом.

## Контракт для игр

Полностью в разделе 13 спеки. Коротко:

1. Игра работает из подпапки `/games/<id>/`: пути к ассетам только относительные или через `import.meta.env.BASE_URL`.
2. Собирается командой `vite build` (лобби подставляет `--base` и `--outDir` само, конфиг игры не трогает).
3. `?embed=1` — без собственного экрана загрузки.
4. Выход: `window.parent.postMessage({ type: 'clickable:exit' }, '*')`.
5. Рекомендуется: `clickable:ready`, когда сцена готова; слушать `clickable:visible` и `clickable:mute`.
6. В embed-режиме игра открывается на своём стартовом экране и ждёт тапа посетителя; `clickable:visible` не запускает игру сам.

Если игра чего-то из этого не умеет, у лобби есть запасной путь: оно само определяет готовность по canvas, Esc выводит в лобби, а через 90 с бездействия лобби возвращается само. Своей кнопки поверх игры у лобби нет (по просьбе заказчика: она перекрывала интерфейс игр), поэтому кнопку выхода в embed-режиме должна рисовать сама игра.

## Видеопревью

`npm run record:previews` открывает каждую собранную игру в Chrome на GPU (для игр с `waitForReady` ждёт их `clickable:ready`), нажимает пробел каждые 3,5 с (Crash: каждые 7 с — запуск, полёт, катапультирование) и пишет 15-секундный ролик 960×540 и постер. Лобби подхватывает их из `public/previews/index.json` при старте. Видео играет только на активном автомате, остальные показывают постер. Ролики не коммитятся (их нужно перезаписывать при каждом обновлении игр). Если превью нет, на экране неоновая заставка с названием.

```bash
npm run build:games
npm run record:previews
npm run build:all
npm run serve
# Chrome в режиме киоска: Esc не выбрасывает из полноэкранного режима

```

## Деплой на Vercel

Только после подтверждения заказчика. Проект Vercel `clickable-lobby` (команда «Rustam's projects»), продакшен: https://clickable-lobby.vercel.app

```bash
npm run build:all
npx vercel deploy dist --prod --yes --project clickable-lobby
```

`--project` деплоит готовую папку без привязки, поэтому каталог `.vercel` в `dist/` не появляется и пересборка ничего не ломает.

`dist/vercel.json` (из `public/`) задаёт долгий кеш для хешированных ассетов.

## Клавиши

| Клавиша | Действие |
|---|---|
| ← / → или A / D | повернуть карусель |
| Enter / пробел | открыть игру |
| Esc | выйти из игры |
| 1–9 | сразу открыть N-ю игру (ведущий) |
| M | звук вкл/выкл |
| F | счётчик FPS |
| T | attract-режим вкл/выкл |

Параметры URL для ведущего и тестов: `?quality=low`, `?fps=1`, `?idle=<сек>` (возврат из игры по простою), `?attractIdle=<сек>`, `?tg=<query>` (параметры тестовой игры в dev).

## Бренд

Логотип, цвета и шрифты берутся из `shared/brand/` через алиас `@brand`.

Исключение: векторный знак Clickable для стеклянной сферы в центре зала лежит в `src/brand-extra/logo-mark.svg` (источник: `Desktop/clickable-landings/assets/logo-mark.svg`). В `shared/brand/` есть только PNG-знак 32×32. Знак стоит добавить в `shared/brand/` отдельным осознанным изменением и переключить импорт в `src/scene/GlassCore.tsx`.

## Качество графики

По умолчанию полное качество: bloom, виньетка и сглаживание SMAA. Канвас рисуется с плотностью пикселей экрана (на телефоне до 3×), но не больше ~3,3 млн пикселей на кадр, поэтому ТВ 1080p остаётся на 1×. Если устройство не держит частоту кадров, лобби само сначала отключает SMAA, затем снижает плотность пикселей (не ниже 1×).

Для слабого ноутбука на стенде есть `?quality=low`: без bloom, виньетки, SMAA и лучей прожекторов, с меньшим числом искр и огней. Замер на Intel UHD при 1920×1080: полное качество около 56 FPS, низкое стабильно 60.

## Фон зала

`src/scene/Backdrop.tsx`, всё на неосвещаемых шейдерах (стена занимает большую часть кадра, живые источники света стоили бы дороже всей сцены):
- изогнутая стена из рифлёных панелей (радиус 17 м, 32 панели); у подножия каждой панели настенный светильник с тёплым конусом света вверх; выше стена уходит в темноту;
- отражения светильников на глянцевом полу;
- четыре луча прожекторов сверху за сценой и пятна света на полу; на вертикальном экране добавляются ещё два луча ближе к центру, иначе узкий кадр их не видит;
- размытые огни (боке) в дымке между стеной и сценой, красные и тёпло-белые.

В градиенты подмешан шум в полшага яркости, чтобы на 8-битных экранах не было полос. По замеру фон не меняет FPS.

## Телефон

На вертикальном экране камера переходит на отдельный ракурс, а кольцо автоматов сжимается по ширине в эллипс: соседние автоматы выглядывают у краёв экрана. Ракурс и сжатие плавно смешиваются с десктопными по соотношению сторон (`portraitBlend` в `src/scene/cameraMath.ts`, константы `CAMERA_PORTRAIT` и `PORTRAIT_SQUASH` в `src/scene/layout.ts`). На горизонтальных экранах всё как раньше.

Что ещё подсказывает, что игр несколько:
- точки под стрелками, по одной на автомат; по точке можно перейти;
- на сенсорном экране плашка «Swipe for more games»;
- карусель сама слегка поворачивается к следующему автомату и возвращается (через 1,4 с и через 9 с), пока посетитель ни разу не листал. Любое касание отменяет этот поворот.
