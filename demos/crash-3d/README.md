# C2 Crash «Ракета»

Офлайн-демо crash-игры на React + three.js. Только виртуальные кредиты.

Заготовка: подробности добавятся в конце проекта.

## Команды

- `npm run dev` — dev-сервер
- `npm run build` — сборка в `dist/`
- `npm test` — юнит-тесты
- `npm run shot -- "?debug=1&freeze=10" shots/a.png [--portrait]` — снимок кадра при запущенном dev-сервере

## Производительность

Замеры на ноутбуке разработки (Intel UHD Graphics, Chrome headless, ANGLE/D3D11). Во время замеров GPU делили другие демо и прогоны Playwright: без облаков сцена давала 8–12 FPS вместо прежних 90–145, поэтому абсолютные цифры сильно занижены. Сравнивать стоит соотношения.

- **Шум облаков** (Perlin-Worley 128³ + погода 512² + синий шум 64²): 0,85–1,1 с в 4 воркерах, в dev и в production-сборке. В одном потоке около 1,8 с. Генерация входит в загрузку: сцена не готова, пока шум не создан.
- **FPS из `<Stats>`, 1920×1080, dpr 1:**
  - `freeze=1.15`: 14;
  - `freeze=1.45`: 10;
  - `freeze=2.0`: 14.
- **FPS из `<Stats>`, портрет 390×844, dpr 2:**
  - `freeze=1.45`: 14;
  - `freeze=2.0`: 20.
- **GPU-время прохода raymarching** (timer query, половинное разрешение):
  - `freeze=1.15`: ≈ 15 мс;
  - `freeze=2.0`: ≈ 10 мс;
  - `freeze=1.45`: ≈ 50 мс. Камера внутри слоя, это худший случай, он длится около секунды за раунд.

  Если облаков слишком много для слабого GPU, первыми крутить `QUALITY.cloudSteps` (72 → 36 вдвое удешевляет проход) и `cloudScale`.
