# C2 Crash «Ракета»

Офлайн-демо crash-игры для стенда Clickable: ракета взлетает, множитель растёт, игрок забирает выигрыш до взрыва. React + three.js, только виртуальные кредиты, без сети во время игры.

## Запуск на стенде

```bash
npm install
npm run build && npm run preview
```

Игра открывается на `http://localhost:4185/`. В Chrome включите полноэкранный режим (F11).

**Откройте игру один раз заранее, в том же профиле Chrome, что и на мероприятии.** При самом первом запуске браузер компилирует шейдеры. На Windows (ANGLE/D3D11) это около 30–45 секунд, всё это время видна заставка с полосой загрузки. Дальше шейдеры берутся из кэша браузера, и загрузка занимает около 10 секунд.

После загрузки стенд сам уходит в демонстрационный режим и играет раунды. Первое касание или клавиша возвращает к экрану ставки с балансом 10 000.

## С телефона

1. Телефон и ноутбук в одной Wi-Fi-сети.
2. IP ноутбука: `ipconfig` → «IPv4-адрес», например `192.168.1.23`.
3. На телефоне откройте `http://192.168.1.23:4185/`. Работает в портретной и альбомной ориентации.

`npm run preview` слушает все сетевые интерфейсы. Если телефон не открывает страницу, разрешите Node.js доступ к частной сети в брандмауэре Windows.

## Без сети

После первого открытия service worker кэширует всю сборку, около 9,6 МБ вместе с текстурами. Дальше игра на ноутбуке открывается без сети.

Браузеры регистрируют service worker только по HTTPS или на `localhost`. По адресу `http://<IP>:4185/` телефон кэш не сохранит, ему нужен запущенный на ноутбуке `npm run preview`.

## Управление

| Действие | Клавиатура | Касание |
|---|---|---|
| Запуск / забрать выигрыш | Space или Enter | большая красная кнопка |
| Ставка | ↑ ↓ | − / + у ставки |
| Порог автокэшаута | ← → | − / + у AUTO |
| Автокэшаут вкл/выкл | A | переключатель AUTO |
| Звук | M | динамик у логотипа |
| Выход в лобби (только `?embed=1`) | Esc | кнопка EXIT |

Демонстрационный режим включается после загрузки и после 45 секунд без действий на экране ставки.

## Режим ведущего

Подготовленный исход действует на следующий раунд игрока, в том числе на первый раунд после выхода из демонстрационного режима.

- Набрать на клавиатуре `HYPER`: следующий раунд улетит в варп, crash-точка от ×40 до ×150.
- Набрать `NUKE`: следующий раунд взорвётся на старте.
- Долгое нажатие на логотип (2 секунды) открывает панель с кнопками `NEXT ROUND: WARP` и `NEXT ROUND: BOOM`. Касание вне кнопок закрывает панель.

Коды работают в любой раскладке: учитываются физические клавиши. Пока исход подготовлен, у логотипа горит маленькая красная точка.

## Встраивание в лобби

С параметром `?embed=1` игра работает внутри лобби (`demos/lobi-3d`):

- вместо заставки чёрный экран до готовности сцены, демонстрационный режим при загрузке не включается;
- в правом верхнем углу кнопка EXIT, Esc делает то же;
- игра отправляет родительскому окну `{ type: 'clickable:ready' }`, когда сцена на экране, и `{ type: 'clickable:exit' }` при выходе;
- принимает `{ type: 'clickable:mute', muted }` только от родительского окна того же origin;
- service worker не регистрируется.

## Debug-параметры

Работают только вместе с `?debug=1`. Без него игнорируются.

| Параметр | Что делает |
|---|---|
| `seed=<целое>` | фиксирует генератор: одинаковая последовательность раундов |
| `freeze=<1…1000>` | держит полёт на этом множителе (`1`: обратный отсчёт на столе) |
| `cam=close\|base\|top\|plume\|pad\|sun` | отладочная камера |
| `shot=<id>` | держит одну эфирную камеру: `padWide`, `padClose`, `groundTele`, `onboard`, `sideChase`, `wide`, `capsuleFollow`, `crashWide`, `sunrise` |
| `rare=sunrise\|aurora\|station\|meteors` | каждый раунд получает это редкое событие; с `freeze` событие замирает на самом зрелищном моменте |

Ещё в debug-режиме:

- счётчик FPS;
- `window.__crash.snap()` возвращает состояние раунда;
- `window.__crash.setNextCrash(x)` задаёт crash-точку следующего раунда;
- `window.__crashReady === true`, когда сцена готова.

Демонстрационный режим после загрузки в debug не включается, чтобы скрипты могли управлять игрой.

Примеры:

```
?debug=1&freeze=60&shot=onboard          варп с бортовой камеры
?debug=1&rare=station&freeze=4.9&shot=sideChase   пролёт станции
?debug=1&rare=sunrise&freeze=2.45&shot=sunrise    восход из-за края Земли
```

## Команды

- `npm run dev`: dev-сервер, `http://localhost:5183/`.
- `npm run build`: сборка в `dist/`.
- `npm run preview`: сборка на `http://localhost:4185/` и по IP в локальной сети.
- `npm test`: юнит-тесты (vitest).
- `npm run e2e`: сценарии Playwright.
- `npm run shot -- "?debug=1&freeze=10" shots/a.png [--portrait] [--eval "<js>"] [--at <секунды>]`: снимок кадра при запущенном dev-сервере.
- `npm run textures`: заново собрать текстуры Земли и Луны из исходников NASA (нужна сеть).
- `npm run icons`: иконки PWA из `public/icon.svg`.

## Производительность

Замеры на ноутбуке разработки.

### Загрузка

Production-сборка, Chrome, ANGLE/D3D11, дискретный GPU (RTX 5060):

- Первый запуск с пустым профилем браузера: сцена готова через 33 секунды. Из них около 23 секунд занимает компиляция примерно 40 шейдерных программ. Освещённые материалы (MeshStandard/MeshPhysical) стоят 0,6–1,4 с каждый, D3D11 компилирует их последовательно.
- Повторный запуск в том же профиле: около 9 секунд.
- Без сети после первого открытия: около 13 секунд.

Что проверено и не помогло: параллельная компиляция (`compileAsync`) и отключение теней прожекторов. Время компиляции не изменилось.

### Облака

Во время этих замеров GPU делили другие демо и прогоны Playwright: без облаков сцена давала 8–12 FPS вместо обычных 90–145. Абсолютные цифры сильно занижены, сравнивать стоит соотношения.

- **Шум облаков** (Perlin-Worley 128³ + погода 512² + синий шум 64²): 0,85–1,1 с в 4 воркерах, в dev и в production-сборке. В одном потоке около 1,8 с. Генерация входит в загрузку: сцена не готова, пока шум не создан.
- **FPS из `<Stats>`, 1920×1080, dpr 1:**
  - `freeze=1.15`: 14;
  - `freeze=1.45`: 10;
  - `freeze=2.0`: 14.
- **FPS из `<Stats>`, портрет 390×844, dpr 2:**
  - `freeze=1.45`: 14;
  - `freeze=2.0`: 20.
- **GPU-время прохода raymarching** (timer query, половинное разрешение):
  - `freeze=1.15`: ≈ 15 мс;
  - `freeze=2.0`: ≈ 10 мс;
  - `freeze=1.45`: ≈ 50 мс. Камера внутри слоя, это худший случай, он длится около секунды за раунд.

Если облаков слишком много для слабого GPU, первыми крутить `QUALITY.cloudSteps` (72 → 36 вдвое удешевляет проход) и `cloudScale` в `src/scene/quality.ts`.
