# C2 Crash «Ракета»

Офлайн-демо crash-игры для стенда Clickable: ракета взлетает, множитель растёт, игрок забирает выигрыш до взрыва. React + three.js, только виртуальные кредиты, без сети во время игры.

## Запуск на стенде

```bash
npm install
npm run build
```

Дальше двойной клик по `stand.cmd`. Он запускает сервер и открывает игру в Chrome:

- на дискретной видеокарте NVIDIA, на лучшем уровне качества;
- на весь экран в режиме киоска;
- со звуком без первого касания.

У Chrome для стенда отдельный профиль, поэтому флаги работают, даже если обычный Chrome уже открыт. Закрыть киоск: Alt+F4.

Вручную: `npm run preview`, игра на `http://localhost:4185/`, в Chrome полноэкранный режим F11.

**Видеокарта.** Игра сама выбирает уровень качества по видеокарте: ultra на дискретной, medium на встроенной, low на телефоне. На встроенной Intel UHD игра идёт на 27–40 FPS, но картинка заметно мягче. Лучший вид даёт NVIDIA: `stand.cmd` включает её сам, для обычного Chrome — Параметры Windows → Система → Дисплей → Графика → Google Chrome → «Высокая производительность». После этого перезапустите Chrome. Проверка: в `chrome://gpu` в строке `GL_RENDERER` должна быть NVIDIA, а с `?debug=1` счётчик в углу показывает 100–144 FPS.

**Откройте игру один раз заранее, в том же профиле Chrome, что и на мероприятии.** При самом первом запуске браузер компилирует шейдеры, это около 20 секунд, всё это время видна заставка с полосой загрузки. Дальше шейдеры берутся из кэша браузера, и загрузка занимает около 10 секунд.

После загрузки стенд сам уходит в демонстрационный режим и играет раунды. Первое касание или клавиша возвращает к экрану ставки с балансом 10 000.

## С телефона

1. Телефон и ноутбук в одной Wi-Fi-сети.
2. IP ноутбука: `ipconfig` → «IPv4-адрес», например `192.168.1.23`.
3. На телефоне откройте `http://192.168.1.23:4185/`. Работает в портретной и альбомной ориентации.

`npm run preview` слушает все сетевые интерфейсы. Если телефон не открывает страницу, разрешите Node.js доступ к частной сети в брандмауэре Windows.

## Без сети

После первого открытия service worker кэширует всю сборку, около 9,6 МБ вместе с текстурами. Дальше игра на ноутбуке открывается без сети.

Браузеры регистрируют service worker только по HTTPS или на `localhost`. По адресу `http://<IP>:4185/` телефон кэш не сохранит, ему нужен запущенный на ноутбуке `npm run preview`.

## Как устроен раунд

Вся игра идёт на одном экране, как в классических crash-играх. Камера одна, без переключений. До старта ракета стоит на столе в левом нижнем углу. После взлёта она наклоняется и по линии графика уходит в правую верхнюю треть экрана, дальше держится там, а мир уходит вниз: облака, Земля, звёзды, варп. Красная линия графика тянется от точки старта к ракете, слева стоит шкала множителя.

Ракета летит минимум 10 секунд: раньше ×4.56 обычный раунд не взрывается, у посетителя есть время посмотреть полёт и забрать выигрыш. Дальше точка взрыва случайная: примерно в трети раундов ракета доходит до ×15, примерно в каждом шестом до варпа (×30+). Взрыв на старте бывает только по команде ведущего.

**Cash out.** Камера переходит с ракеты на спасательную капсулу: с парашютом, если раунд закончился низко, или с тормозными двигателями выше. Под капсулой карточка выигрыша, она держится до следующего раунда. Ракета улетает из кадра, и её взрыв, если он будет, происходит за кадром.

## Управление

| Действие | Клавиатура | Касание |
|---|---|---|
| Запуск / забрать выигрыш | Space или Enter | большая красная кнопка |
| Ставка | ↑ ↓ | − / + у ставки |
| Порог автокэшаута | ← → | − / + у AUTO |
| Автокэшаут вкл/выкл | A | переключатель AUTO |
| Звук | M | динамик у логотипа |
| Выход в лобби (только `?embed=1`) | Esc | кнопка EXIT |

Демонстрационный режим включается после загрузки и после 45 секунд без действий на экране ставки.

## Режим ведущего

Подготовленный исход действует на следующий раунд игрока, в том числе на первый раунд после выхода из демонстрационного режима.

- Набрать на клавиатуре `HYPER`: следующий раунд улетит в варп, crash-точка от ×40 до ×150.
- Набрать `NUKE`: следующий раунд взорвётся на старте.
- Долгое нажатие на логотип (2 секунды) открывает панель с кнопками `NEXT ROUND: WARP` и `NEXT ROUND: BOOM`. Касание вне кнопок закрывает панель.

Коды работают в любой раскладке: учитываются физические клавиши. Пока исход подготовлен, у логотипа горит маленькая красная точка.

## Встраивание в лобби

С параметром `?embed=1` игра работает внутри лобби (`demos/lobi-3d`):

- вместо заставки с логотипом только тонкая полоса загрузки, демонстрационный режим при загрузке не включается;
- кнопка EXIT и Esc работают с первой секунды, в том числе пока игра грузится;
- в правом верхнем углу кнопка EXIT, Esc делает то же;
- игра отправляет родительскому окну `{ type: 'clickable:ready' }`, когда сцена на экране, и `{ type: 'clickable:exit' }` при выходе;
- принимает `{ type: 'clickable:mute', muted }` только от родительского окна того же origin;
- service worker не регистрируется.

## Debug-параметры

Работают только вместе с `?debug=1`. Без него игнорируются.

| Параметр | Что делает |
|---|---|
| `seed=<целое>` | фиксирует генератор: одинаковая последовательность раундов |
| `freeze=<1…1000>` | держит полёт на этом множителе (`1`: обратный отсчёт на столе) |
| `cam=close\|base\|top\|plume\|pad\|sun` | отладочная камера |
| `quality=ultra|medium|low` | уровень качества вместо автовыбора по видеокарте |
| `rare=sunrise\|aurora\|station\|meteors` | каждый раунд получает это редкое событие; с `freeze` событие замирает на самом зрелищном моменте |

Ещё в debug-режиме:

- счётчик FPS;
- `window.__crash.snap()` возвращает состояние раунда;
- `window.__crash.setNextCrash(x)` задаёт crash-точку следующего раунда;
- `window.__crashReady === true`, когда сцена готова.

Демонстрационный режим после загрузки в debug не включается, чтобы скрипты могли управлять игрой.

Примеры:

```
?debug=1&freeze=60                     варп
?debug=1&freeze=15&quality=medium      космос на уровне medium
?debug=1&rare=station&freeze=4.9       пролёт станции
?debug=1&rare=sunrise&freeze=2.45      восход из-за края Земли
```

## Команды

- `npm run dev`: dev-сервер, `http://localhost:5183/`.
- `npm run build`: сборка в `dist/`.
- `npm run preview`: сборка на `http://localhost:4185/` и по IP в локальной сети.
- `npm test`: юнит-тесты (vitest).
- `npm run e2e`: сценарии Playwright.
- `npm run shot -- "?debug=1&freeze=10" shots/a.png [--portrait] [--eval "<js>"] [--at <секунды>]`: снимок кадра при запущенном dev-сервере; `--base http://127.0.0.1:4185/` снимает production-сборку.
- `npm run textures`: заново собрать текстуры Земли и Луны из исходников NASA (нужна сеть).
- `npm run icons`: иконки PWA из `public/icon.svg`.

## Производительность

Замеры на ноутбуке разработки.

### Загрузка

Production-сборка, Chrome, ANGLE/D3D11:

- Первый запуск с пустым профилем браузера: сцена готова примерно через 18 секунд на RTX 5060 и через 21 секунду на Intel UHD. Почти всё это время уходит на компиляцию шейдеров: освещённые материалы стоят 0,6–1,4 с каждый, D3D11 компилирует их последовательно.
- Повторный запуск в том же профиле: около 10 секунд.
- Без сети после первого открытия: около 13 секунд.

Все шейдеры компилируются за заставкой. При загрузке сцена один раз рисуется целиком во внутренний буфер, вместе со скрытыми объектами: Землёй, варпом, обломками, капсулой, редкими событиями (`src/scene/prewarm.ts`). Поэтому в раунде нет рывков от компиляции, даже при самом первом запуске.

Что проверено и не помогло: параллельная компиляция (`compileAsync`) и отключение теней прожекторов. Время компиляции не изменилось.

### FPS

Минимальный FPS за полсекунды на каждом этапе раунда, долетевшего до варпа (×200). Production-сборка, Chrome, единый вид, уровень качества выбран автоматически:

| GPU, экран, уровень | Отсчёт | Этапы 0–2 | Этапы 3–4 | Варп | Взрыв |
|---|---|---|---|---|---|
| RTX 5060, 1920×1080, ultra | 113 | 58–108 | 107–110 | 108 | 115 |
| RTX 5060, портрет 390×844 (dpr 2), ultra | 112 | 107–117 | 117 | 102 | 116 |
| Intel UHD, 1920×1080, medium | 39 | 34–47 | 32 | 33 | 33 |
| Intel UHD, портрет 390×844 (dpr 2), low | 69 | 61–110 | 83–85 | 83 | 77 |

Минимум 58 на этапе 0 у RTX — это сам момент отрыва от стола, дальше 100+. До перехода на единый вид и уровни качества Intel UHD давала 7–16 FPS.

**Уровни качества** (`src/scene/quality.ts`). Medium рисует 3D в 0,7 разрешения экрана (интерфейс остаётся чётким), обходится без хроматической аберрации и мокрого отражения стола, у него меньше шагов облаков, частиц дыма и теней. Low для телефонов рисует 1–1,25 пикселя на CSS-пиксель, без god rays и бликов объектива. На встроенной видеокарте кадр упирается в число полноэкранных проходов пост-обработки при 1080p, поэтому главные рычаги — разрешение 3D и число проходов, а не отдельные объекты сцены.

### Облака

Замеры при разработке облаков, до уровней качества. Во время этих замеров GPU делили другие демо и прогоны Playwright: без облаков сцена давала 8–12 FPS вместо обычных 90–145. Абсолютные цифры сильно занижены, сравнивать стоит соотношения.

- **Шум облаков** (Perlin-Worley 128³ + погода 512² + синий шум 64²): 0,85–1,1 с в 4 воркерах, в dev и в production-сборке. В одном потоке около 1,8 с. Генерация входит в загрузку: сцена не готова, пока шум не создан.
- **FPS из `<Stats>`, 1920×1080, dpr 1:**
  - `freeze=1.15`: 14;
  - `freeze=1.45`: 10;
  - `freeze=2.0`: 14.
- **FPS из `<Stats>`, портрет 390×844, dpr 2:**
  - `freeze=1.45`: 14;
  - `freeze=2.0`: 20.
- **GPU-время прохода raymarching** (timer query, половинное разрешение):
  - `freeze=1.15`: ≈ 15 мс;
  - `freeze=2.0`: ≈ 10 мс;
  - `freeze=1.45`: ≈ 50 мс. Камера внутри слоя, это худший случай, он длится около секунды за раунд.

Если облаков слишком много для слабого GPU, первыми крутить `QUALITY.cloudSteps` (72 → 36 вдвое удешевляет проход) и `cloudScale` в `src/scene/quality.ts`.

## Проверка на телефоне

Автотесты гоняют игру в Chrome на ноутбуке с эмуляцией телефона. Настоящий телефон проверяет человек:

1. Запустить на ноутбуке `npm run build && npm run preview`, открыть на телефоне `http://<IP ноутбука>:4185/?debug=1` (раздел «С телефона»).
2. Дождаться конца заставки и записать время загрузки.
3. Сыграть 5 раундов: хотя бы один забрать на ×5–8, один довести до взрыва, один довести до варпа. Для варпа зажмите логотип на телефоне на 2 секунды и выберите `NEXT ROUND: WARP`: у каждого устройства своя игра, код `HYPER` на ноутбуке на телефон не действует.
4. Смотреть на счётчик FPS в левом верхнем углу: записать минимум на старте, в облаках (×1,3–1,6), в космосе и в варпе.
5. Повернуть телефон посреди полёта: раунд продолжается, кнопка на месте.
6. Проверить звук после первого касания и кнопку динамика.
7. Следить, не пропадает ли картинка: чёрный экран или застывший кадр означает потерю WebGL-контекста, обычно от нехватки памяти (одни текстуры Земли 8K занимают около 360 МБ видеопамяти).

Телефон сам получает уровень `low`. Если FPS всё равно ниже 30 или контекст теряется, следующий шаг — урезать `LOW` в `src/scene/quality.ts`: меньше шагов облаков, разрешение 1, текстуры Земли 4K (их нужно собрать `npm run textures`).
